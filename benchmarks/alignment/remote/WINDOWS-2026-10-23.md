# Windows amd64 validation — 2026-10-23

Windows 11 on the same Ryzen 5 7600X used for Linux testing (dual boot).
Native backend detection reported `GOOS=windows`, `GOARCH=amd64`, `avx2-16`.
Both scalar and SIMD alignment unit suites passed, including vector lane checks,
long-path/scoring comparisons and scalar/platform equivalence tests.
The original FASTA regression was skipped in the initial run; it passed in
both backends on the corrected run described below. Full-input PAF hashes
and repeat-rich benchmarks have not been measured on Windows.

The initial wrapper reported failure in its CPU-mask check: with
`GODEBUG=cpu.avx2=off`, the backend remained `avx2-16`, violating the wrapper's
expected `scalar` backend. Both DP tests in that process still passed.
The subsequent AVX-512-mask step was not reached.

Inspection of the build toolchain (Go 1.27.2) identifies the cause in
`src/runtime/proc.go`: `getGodebugEarly` returns no environment string for
Windows; `schedinit` calls `cpuinit` before `goenvs`, and the later Windows
GODEBUG parsing does not reinitialize CPU features. Therefore environment CPU
masking is ineffective in this Windows build. This does not indicate an
alignment or runtime CPU-detection failure. The corrected Windows wrapper
explicitly skips unsupported masking checks, retaining both native unit suites.
Linux feature-mask validation remains recorded separately.

The corrected bundle reuses the exact same executable bytes. Its wrapper
passed on the second Windows run, including the original FASTA regression.
